# aIdea 平台与插件规范

本文档定义 aIdea 的插件术语、职责边界和生命周期。实现插件或调整平台能力前必须先遵守本文档。

## 术语

| 术语 | 定义 |
| --- | --- |
| aIdea 壳 | 本地应用平台，负责插件目录、生命周期、运行状态、日志、平台组件和自身更新。 |
| 内置插件 | 代码位于 aIdea 仓库，随 aIdea 一起构建、发布和更新的应用。 |
| 官方应用 | 独立 GitHub 或 GitLab 仓库的自研应用，由 aIdea 官方应用市场预设收录。 |
| 官方应用市场 | 随 aIdea 发布的官方仓库收录目录；完整应用定义由各应用仓库根目录 `aidea.yaml` 提供，不是远程市场服务。 |
| 平台组件 | aIdea 可选提供的数据目录、日志目录、本地加密存储、通知和命令行入口。 |
| 业务数据 | 插件自己维护的数据库、配置、迁移和文件。 |

当前只开发内置应用和官方应用。第三方应用市场、自定义应用安装、自动发现、应用 SDK 和多作者权限系统不属于现行产品能力；需要时必须单独设计。

## 插件边界

内置插件的代码位于 `shell-frontend/src/builtin-apps/<app-id>/`，随 aIdea 构建。内置插件使用本仓库的前端、Rust IPC、SQLite 和 UI 规范。

官方应用位于独立仓库。私有 GitLab 仓库只在公司网络可访问时，由 aIdea 复用当前用户的 Git 凭据和 SSH 配置。每个官方应用仓库必须提供根目录 `aidea.yaml`；aIdea 仓库只维护其是否被官方市场收录和仓库地址。

| aIdea 管理 | 插件管理 |
| --- | --- |
| 安装、更新、卸载 | 业务代码和业务 UI |
| 启动、停止、健康检查 | 业务 SQLite、配置和迁移 |
| WebView、日志、运行状态 | 业务网络请求、错误处理和数据策略 |
| 官方市场展示、aIdea 自身更新 | 业务数据保留和清理策略 |

插件卸载默认只删除其源码、依赖和运行环境，保留业务数据。删除业务数据必须是单独的、明确确认的操作。

## 生命周期

官方插件按以下流程运行：

```text
官方目录展示 -> 用户安装 -> 校验定义并展示执行内容
-> 获取固定版本源码 -> 安装依赖 -> 启动 -> 健康检查 -> WebView 展示
-> 更新或卸载
```

更新只能替换平台管理的源码、依赖和运行环境，不得覆盖插件业务数据。安装、更新、启动失败时，aIdea 保留错误日志和已知可运行版本，不自动删除用户数据。

单个官方应用的定义、安装记录、启动或健康检查异常必须隔离为应用异常状态；aIdea 壳继续加载其他应用。异常应用保留在顶部菜单和应用管理中，由用户查看错误、日志并执行刷新市场、更新或卸载。

## 平台组件

平台组件是可选能力，不提供 SDK。官方插件通过 aIdea 注入的环境变量和 `aidea` 命令使用；完整接口见 [platform-cli.md](platform-cli.md)。

## 通信边界

- Tauri IPC 只供 aIdea 壳前端和内置插件使用。它是仓库内部的 Rust 命令接口，不是官方应用的接入协议。
- 内置应用前端统一通过 `shell-frontend/src/lib/ipc.ts` 调用 Tauri IPC；业务组件不得直接调用 `invoke`，以保持参数、返回类型和错误处理一致。
- 官方应用不得依赖 `@tauri-apps/api`、`window.__TAURI__`、Rust 命令名或壳前端的 IPC 封装；这些实现可以随 aIdea 内部版本调整。
- 官方应用与 aIdea 的平台通信统一走 `AIDEA_COMMAND` 指向的 `aidea` 命令。命令的参数、输出、错误和最低 aIdea 版本必须在 [platform-cli.md](platform-cli.md) 中定义后，应用才能依赖。
- 官方应用的浏览器页面不直接执行平台命令；需要平台能力时由应用自己的服务进程调用 `AIDEA_COMMAND`，再通过应用内部接口提供给页面。
- 当前没有通用 SDK、任意插件 HTTP API 或跨应用共享数据库。新增平台能力先增加一个明确的命令契约，不为未来需求预留抽象。

数据、日志、SQLite 和本地加密存储的规则见 [data-layout.md](data-layout.md) 与 [storage.md](storage.md)。

## 应用设置

每个应用都必须有设置详情页。详情页统一在 aIdea「设置 -> 应用管理」弹窗内部打开，aIdea 只提供列表、二级导航和重置授权，不解析应用字段，也不建立共享配置表。

- 内置应用在壳内注册自己的设置组件；组件通过 `shell-frontend/src/lib/ipc.ts` 使用平台能力。尚未提供具体字段的内置应用仍显示详情页，但显示空配置状态。
- 官方应用必须提供固定的本地 `/settings` 页面。aIdea 先确保应用服务运行，再在 WebView 中打开该地址。
- 只有声明 `process` 的应用在详情页显示“随 aIdea 启动”；应用管理列表不显示该开关。
- 应用管理列表使用滑块开关控制应用是否显示在 aIdea 顶部菜单；重置按钮只出现在详情页。
- 应用的简单非敏感配置可以是 `app-data/<app-id>/settings.json`；有关系和迁移需求时使用应用自己的 SQLite；凭据使用平台敏感存储。
- `settings.reset_command` 是可选能力。aIdea 先请求 Touch ID，再停止运行中的应用、执行命令并按原状态恢复；重置失败不得删除或覆盖业务数据。
- 卸载、更新和重新安装同一 `app_id` 都保留应用数据，应用自己负责默认值、版本迁移和兼容性检查。

内置应用的 `reset_command` 使用已注册的处理器标识，不执行任意 shell；当前 DevTools 的处理器只删除自己的 `settings.json`。

## 独立运行

官方应用必须支持脱离 aIdea 启动核心业务，便于开发、测试和故障排查，但不需要复制 aIdea 的桌面壳、市场、更新器或进程管理。应用在有 aIdea 环境变量时使用平台目录，独立启动时使用自身默认目录。
