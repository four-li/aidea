# 统一调试日志设计

## 目标

提供一个统一的「调试」页面，让用户能够从 aIdea、内置应用和官方应用中找到可复制的故障证据。日志始终开启，所有应用遵守同一套级别、格式、脱敏和目录契约。

本设计采用混合收集模式：aIdea 负责平台与生命周期日志，子应用负责业务日志；aIdea 负责统一保存、清理、统计和查看。

## 非目标

- 不提供跨应用合并的“全部日志”时间线。
- 不提供诊断包、远程上传、数据库导出或应用级别的独立配置。
- 不提供未读状态、单行复杂详情面板或普通业务点击审计。
- 不读取、复制或打包应用数据库、配置、邮件正文、通知正文或凭据。

## 全局级别

日志策略保存在 `shell.config.json`，所有内置应用和官方应用共用一套设置：

```json
{
  "app_settings": {},
  "log_level": "standard",
  "log_retention_days": 30,
  "log_max_total_mb": 500
}
```

用户界面显示三个档位：

| UI 名称 | 内部值 | 记录范围 |
| --- | --- | --- |
| 精简 | `minimal` | `WARN`、`ERROR`；关键生命周期失败必须记录 |
| 标准 | `standard` | `INFO`、`WARN`、`ERROR`；默认值 |
| 调试 | `debug` | `DEBUG` 及以上，包含额外排查上下文 |

级别是全局设置，不支持按应用覆盖。日志级别只控制可选日志；端口占用、市场请求失败、启动失败、健康检查失败、进程异常退出和日志系统失败等关键错误始终按 `ERROR` 保留。

默认保存 30 天、总容量 500 MB。旧配置缺少新字段时使用默认值。

## 日志目录与归属

```text
~/Library/Application Support/aIdea/logs/
├── aidea/system/
├── builtin/<app-id>/{runtime,platform}/
└── official/<app-id>/{runtime,install,platform}/
```

- `aidea/system/`：aIdea 壳自身的启动、配置、市场、更新、日志系统和无法归属应用的异常。
- `builtin/<app-id>/runtime/`：内置应用服务输出；没有独立服务时可以为空。
- `builtin/<app-id>/platform/`：内置应用前端未处理异常、Promise rejection、IPC 失败和关键生命周期事件。
- `official/<app-id>/runtime/`：官方应用 stdout/stderr 和应用运行输出。
- `official/<app-id>/install/`：下载、状态码、SHA-256 校验、解压、staging 健康检查及其输出。
- `official/<app-id>/platform/`：端口检查、启动/停止/重启、健康检查、进程退出和壳侧失败原因。

历史 `logs/<app-id>/app.log` 和 `install.log` 只兼容读取，新的写入不再使用旧路径。应用数据、安装包、市场缓存、运行状态和备份不属于日志清理范围。

## 统一日志格式

日志以可直接复制的文本行保存，不引入 JSON：

```text
2026-08-16 02:47:56  INFO   market   请求官方市场完成 status=200 duration=412ms
2026-08-16 02:48:01  WARN   process  端口 127.0.0.1:43131 已被占用
2026-08-16 02:48:04  ERROR  process  启动项目追踪失败
```

- 时间显示格式固定为 `YYYY-mm-dd HH:ii:ss`，实际输出使用本地时间，例如 `2026-08-16 02:47:56`。
- 级别固定为 `DEBUG`、`INFO`、`WARN`、`ERROR`。
- `source` 使用稳定的小写标识，例如 `market`、`process`、`lifecycle`、`frontend`、`ipc`、`stdout`、`stderr`。
- 一条事件只占一行，换行转义为字面量 `\n`。
- 没有级别的历史 stdout/stderr 按 `INFO` 兼容显示。
- 任何日志写入失败都不能阻塞原业务操作；失败本身尽力记录并反馈给用户。

官方应用启动时注入 `AIDEA_LOG_LEVEL=warn|info|debug`。应用必须根据该变量控制可选输出，并通过 stdout/stderr 或 `AIDEA_APP_LOG_DIR` 下的 `.log` 文件遵守同一格式。应用不得输出密码、授权码、OAuth 令牌、API Key、邮件正文、通知正文或敏感 URL 查询参数。

## 日志覆盖矩阵

所有失败和异常在错误产生处写入日志，不能只依赖前端 toast。成功只记录关键生命周期，不记录普通业务点击。

| 事件 | 归属 | 频道 | 级别 |
| --- | --- | --- | --- |
| aIdea 启动、配置读取/保存、窗口/前端异常、IPC 失败、更新 | aIdea | 平台事件 | INFO/ERROR |
| 市场请求开始/完成、状态码、耗时、解析、校验、缓存替换 | aIdea | 平台事件 | DEBUG/INFO/ERROR |
| 安装下载、HTTP 状态、SHA-256 校验、解压、staging 健康检查、回滚 | 对应官方应用 | 安装与更新 | INFO/ERROR |
| 启动前端口检查、端口占用、端口释放 | 对应官方应用 | 平台事件 | INFO/WARN/ERROR |
| 启动、停止、重启、健康检查、超时、进程退出、崩溃和孤儿进程恢复 | 对应官方应用 | 平台事件 | INFO/ERROR |
| 官方应用 stdout/stderr | 对应官方应用 | 运行日志 | 按应用输出 |
| 内置应用 stdout/stderr、前端异常、Promise rejection、IPC 错误 | 对应内置应用 | 运行/平台事件 | 按级别 |
| 日志设置、自动清理、手动清理、轮转和写入失败 | aIdea | 平台事件 | INFO/ERROR |

市场错误至少记录请求主机和路径、状态码、耗时和错误类型；禁止记录响应正文、Token 或敏感查询参数。端口错误至少记录应用 ID、地址、系统错误和可执行的排查上下文。

## 混合收集边界

### aIdea 壳

aIdea 的 Rust 平台代码通过统一日志函数记录平台事件和官方应用生命周期。端口占用必须在启动前记录，市场刷新失败（包括 403/401/429/5xx）必须在请求错误处记录，启动和健康检查失败必须在返回 IPC 错误前记录。

aIdea 前端只补充 WebView 自身无法由 Rust 观察到的未处理错误和 Promise rejection；普通 toast 不自动当作日志，避免重复记录。

### 内置应用

内置应用通过壳提供的日志函数记录自身关键业务事件。前端未处理异常和 IPC 调用失败统一进入对应应用日志；不采集所有 `console.log`。

### 官方应用

官方应用业务日志由应用自己输出到 stdout/stderr 或 `AIDEA_APP_LOG_DIR` 下的 `.log` 文件。aIdea 捕获 stdout/stderr，分别写入运行或 staging 安装日志；应用负责保证输出格式、级别和敏感信息边界。

## 清理与滚动

日志按日期和固定单文件容量滚动。自动清理顺序：

1. 删除超过保存天数的非当前日志文件。
2. 若总容量仍超过上限，从最旧的非当前文件开始删除，直到达标。
3. 自动清理不删除正在写入的当前文件；必要时先滚动再清理。

高级设置中的「清理日志」是显式危险操作，确认后删除 `logs/` 下全部日志，包括当前文件；不删除其他用户数据或市场缓存。成功只显示 toast，不重新写入成功日志；失败写入 aIdea 平台日志并显示错误。

自动清理在 aIdea 启动、日志滚动和保存日志策略后执行。

## 统一调试页面

### 入口与导航

- 右上角账户菜单增加「调试」，使用 Lucide `Bug` 图标，进入统一调试页面并默认选中 aIdea。
- 应用管理卡片的「调试」入口进入同一页面并预选当前应用。
- 高级设置不再提供单独的 aIdea 日志入口。
- 页面是全屏二级页面，替换主内容区，左上角提供返回按钮；不使用 Dialog 或 Sheet。

### 页面布局

- 左侧固定来源菜单，按 aIdea、内置应用、官方应用分组。
- 每个来源旁显示当前保留日志中的 `WARN+` 总数；不做未读状态，查看不会改变计数。
- 右侧显示当前来源的结构化日志行：时间、级别、来源和消息；长消息自动换行。
- 官方应用提供「运行日志」「安装与更新」「平台事件」Tab；内置应用提供「运行日志」「平台事件」Tab；aIdea 只提供「平台事件」。
- 工具栏提供频道切换、级别筛选、关键词搜索、暂停/继续刷新和复制当前日志。
- 每次读取最多显示最近 200 行，按用户指定的时间格式显示。复制范围是当前来源和频道的可见文本，不生成诊断包。

## IPC 与数据接口

实现需要补充以下平台能力：

- 日志级别读取和保存。
- 按来源/频道读取最近日志。
- 列出调试页面来源及其 `WARN+` 计数。
- 清理全部日志。
- aIdea、内置应用错误写入统一日志。

日志读取失败只影响当前来源或频道，其他来源仍可切换；清理和设置保存失败必须返回可显示的错误。

## 验收与测试

自动测试至少覆盖：

- 三档级别默认值、校验、保存和官方应用环境变量。
- 日志行级别过滤、旧无级别日志按 INFO 兼容。
- 端口占用、市场 403、启动失败、健康检查失败和进程退出均写入正确来源/频道。
- stdout/stderr 和 staging 输出的归属与读取。
- WARN+ 计数不包含 INFO/DEBUG。
- 自动按日期/容量清理，手动清理删除当前日志但不触及应用数据和市场缓存。
- 历史 `app.log`、`install.log` 兼容读取。
- 调试页来源切换、频道差异、筛选、暂停刷新和复制当前日志。

手工验收至少包括：制造一个端口占用、一次市场 403、一次 staging 健康检查超时和一次内置 IPC 失败，确认均能从「调试」页面复制完整错误证据；切换三档级别确认日志量差异；执行「清理日志」确认应用数据、安装包和市场缓存仍在。
