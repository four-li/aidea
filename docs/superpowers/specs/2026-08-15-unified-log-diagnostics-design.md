# 统一日志与诊断设计

## 目标

让用户能在 aIdea 内查看、复制并提供可追溯的故障证据。日志必须覆盖 aIdea 壳、内置应用和官方应用的运行、安装、更新、启动、停止、健康检查与异常退出，同时保留现有应用数据隔离和敏感信息边界。

本设计将日志作为 aIdea 平台能力，而不是每个应用自行拼装的页面功能。

## 非目标

- 不提供日志等级、调试开关、单应用覆盖或应用级保留策略。
- 不提供搜索、筛选、远程上传、ZIP 诊断包、数据库导出或跨应用聚合视图。
- 不读取、复制或打包应用数据库、配置、邮件正文、通知正文或凭据。
- 不对日志进行猜测式自动脱敏。官方应用继续负责不把敏感值写入日志。

## 全局策略

日志始终开启，所有应用共用一套策略，保存到 `shell.config.json`：

```json
{
  "app_settings": {},
  "log_retention_days": 30,
  "log_max_total_mb": 500
}
```

- `log_retention_days` 默认 `30`。
- `log_max_total_mb` 默认 `500`。
- 旧配置缺少字段时使用默认值，不迁移或改写旧文件。
- 设置不支持按应用分级、关闭或覆盖。

## 目录与归属

```text
~/Library/Application Support/aIdea/logs/
├── aidea/
│   └── system/                     # 壳自身启动、更新、全局异常
├── builtin/<app-id>/
│   ├── runtime/                    # 内置服务 stdout/stderr；无服务时为空
│   └── platform/                   # IPC、服务生命周期、未处理前端异常
└── official/<app-id>/
    ├── runtime/                    # 官方应用 stdout/stderr、退出状态
    ├── install/                    # 下载、校验、解压、staging 健康检查及输出
    └── platform/                   # 壳对该应用的生命周期、失败原因
```

内置应用与官方应用使用不同根目录，即使未来出现同名 ID 也不混淆。AI 网关属于内置应用，使用 `builtin/ai-gateway/`；其本地服务的输出属于 `runtime/`。

旧的 `logs/<app-id>/app.log` 和 `logs/<app-id>/install.log` 是历史证据。日志读取必须兼容它们，新的写入不再创建这两个位置。

## 写入规则

### aIdea 壳

`aidea/system/` 记录壳启动、关闭、更新检查与安装、无法归属到某个应用的异常。日志行使用本地时间 `YYYY-MM-DD HH:mm:ss`，并包含事件来源、结果和必要的错误上下文；时区只记录在日志文件元数据中，不在每行重复显示。

### 官方应用

- 子进程 stdout/stderr 由壳捕获并写入 `official/<app-id>/runtime/`；每行附加采集时间与 `stdout` 或 `stderr` 来源。
- 启动、停止、重启、端口占用、健康检查、启动超时、退出码和终止信号写入 `official/<app-id>/platform/`。
- 下载、SHA-256 校验、解压、staging 启动及健康检查写入 `official/<app-id>/install/`。
- staging 子进程 stdout/stderr 也写入 `install/`。失败时只删除 staging 安装文件，不删除其日志。

### 内置应用

- 内置服务的 stdout/stderr 使用与官方应用相同的采集规则，写入 `builtin/<app-id>/runtime/`。
- 内置应用生命周期、Rust IPC 命令失败、WebView 未处理异常和未处理 Promise 拒绝写入 `builtin/<app-id>/platform/`。
- 不采集所有 `console.log`；它们通常是开发噪声，不能替代用户可用的诊断记录。未处理错误与 IPC 失败仍必须记录。

### 内容边界

壳不得写入 AI 网关访问令牌、密码、授权码、OAuth 令牌、邮件正文、通知正文、数据库内容或本地文件正文。官方应用契约继续要求应用自身不得将这些内容输出到 stdout、stderr 或文件日志。

## 滚动与清理

日志按日期和单文件容量滚动，运行中的长寿命服务也必须能在跨日或达到单文件上限后继续写入新文件。每个文件的文件名包含日期和递增序号；单文件上限是内部固定值，不向用户暴露额外设置。

清理顺序：

1. 删除修改时间早于 `log_retention_days` 的非当前日志文件。
2. 递归计算 `logs/` 总大小；若仍超过 `log_max_total_mb`，从最旧的非当前文件开始删除，直到总量达标。
3. 当前正在写入的文件不删除；如需释放空间，先滚动，再清理旧文件。

清理在 aIdea 启动、日志滚动、保存日志策略后执行。它只处理 `logs/`，绝不触及 `app-data/`、`apps/installed/`、`runtime/` 或 `backups/`。

## 用户界面

### 应用管理

应用管理中的“日志”入口打开独立的日志工作台，占用足够宽度以阅读和复制长错误，不使用现有的底部 Sheet。工作台顶部固定显示应用图标、名称、版本、本地地址和当前运行状态；右侧固定显示暂停自动刷新与“复制当前内容”操作。

来源使用标题区下方的横向 Tab，而不是侧栏：

- 官方应用：`应用运行`、`安装与更新`、`aIdea 事件`。
- 内置应用：`应用运行`、`aIdea 事件`。
- 没有独立进程的内置页面：`应用运行`只显示捕获到的未处理前端错误和 IPC 失败；没有记录时显示“暂无运行日志”。

每个 Tab 的日志区上方显示来源名称、最近 200 行和自动刷新状态。日志正文使用等宽字体，时间统一显示为 `YYYY-MM-DD HH:mm:ss`；`stdout`、`stderr` 和壳事件作为来源列展示，错误和警告可用颜色辅助识别。每个 Tab 读取保留范围内的最近日志、每两秒刷新、支持暂停，并提供“复制当前内容”。复制范围就是当前可见文本，不生成文件、不访问剪贴板以外的数据，也不导出数据库。

### 高级设置

“高级”页增加“日志”区块：

- 保留时间选择器，默认 30 天。
- 总容量选择器，默认 500 MB。
- “查看 aIdea 日志”按钮，打开相同的日志工作台并只显示 `aidea/system/`。

保存后立即执行一次日志清理，并显示保存或清理失败的错误提示。无需重启 aIdea。

## 错误处理

- 日志无法写入时，原业务操作不能因为诊断失败而被阻塞；壳尽力写入，并将写入失败显示为用户可见错误。
- 日志目录创建、轮转、读取与清理失败必须携带路径与系统错误上下文，但不携带敏感环境变量。
- 子进程启动失败、健康检查失败或异常退出必须先写平台日志，再返回现有的 IPC 错误和 UI 提示。
- 单个应用日志损坏或不可读只影响该应用对应 Tab，不阻塞其他应用与 aIdea 日志。

## 契约与版本

本设计会更新以下权威文档：

- `docs/guide/aidea-platform.md`：日志职责、可查看日志和生命周期失败留存。
- `docs/guide/aidea-official-app.md`：官方应用 stdout/stderr 与日志目录约束。
- `docs/guide/aidea-storage.md`：新的日志目录、滚动和清理边界。

日志界面、设置、文件布局和失败行为都属于用户可见功能与数据格式变更，实施时 aIdea 版本必须递增。

## 验收与测试

自动测试至少覆盖：

- 新旧配置的默认日志策略与保存。
- 官方应用 stdout、stderr、启动失败、健康检查失败、退出码或信号的记录位置。
- staging 健康检查失败后输出仍可读。
- 内置服务日志与内置 WebView 未处理错误、IPC 失败记录。
- 按日期删除、按容量从最旧文件删除、当前写入文件不被删除。
- 历史 `app.log` 和 `install.log` 仍显示。
- 官方与内置应用的 Tab 差异、高级页设置、复制当前 Tab 内容。

手工验收至少包括：让一个官方应用输出 stderr 并异常退出；让 staging 健康检查超时；在内置应用制造 IPC 失败；确认三个场景都能从对应日志入口复制到完整错误信息；调整为极短保留期和较小容量后确认不会误删应用数据。
