# 官方应用异常隔离设计

> **历史设计记录**：本文件只记录当时设计，不是当前平台契约。当前规则以仓库根目录 `AGENTS.md` 和 `docs/guide/` 为准。

## 目标

aIdea 壳必须能够在官方应用缺失、定义损坏、进程启动失败、健康检查失败或安装记录过期时继续运行。异常应用不能让 `list_apps` 失败，也不能让顶部导航和设置页整体加载失败。

## 状态模型

在 `AppManifest` 增加可选的 `issue` 字段，表达定义、安装记录等加载期问题；在 `AppState` 增加同样结构的可选 `issue` 字段，表达启动、停止和健康检查等运行期问题。正常应用没有该字段；异常应用仍保留 `id`、名称、版本和安装路径，并携带：

- `level`：当前只使用 `warning`。
- `message`：面向用户的异常原因和下一步动作。
- `updated_at`：最近一次发现异常的时间；没有持久化要求时可由本次加载生成。

异常应用仍以可展示状态返回，不能用 `Result` 让单个应用错误中断整个列表。无法恢复完整定义的旧安装记录使用占位 manifest；如果连应用记录本身损坏，则记录错误并跳过该项，不影响其他应用。前端展示时以 `manifest.issue ?? state.issue` 作为最终异常状态。

## 后端边界

1. `manifest::load_all_manifests` 汇总内置、本地和官方应用时，对每个官方应用独立处理错误。
2. 官方应用定义、进程状态和安装记录的错误转换为 `issue`；壳配置、IPC 初始化和数据库初始化错误仍按壳级错误返回。
3. 异常消息写入该应用的日志目录，并保留最近一次异常状态。相同应用、相同错误在一次加载周期内不重复打印。
4. `ProcessManager` 在内存中保存每个应用最近一次运行错误，序列化到 `AppState.issue`；启动成功后清除该错误。启动、停止、健康检查失败只能更新该应用状态；其他应用继续加载和运行。
5. 现有 `install-state.yaml` 没有定义快照且市场缓存缺失时，生成占位应用；提示“刷新市场后更新或卸载”，不再使用 `eprintln!` 反复刷屏。

## 前端展示

- 顶部应用菜单保留异常应用，图标、名称置灰，并显示警告图标；点击仍能进入异常详情页。
- 内容区对 `issue` 应用显示异常说明、最近错误信息和可执行操作：打开应用管理、刷新官方市场、查看日志。
- 应用管理页显示异常 Badge、异常信息和日志入口；启动/停止等无法执行的操作应禁用或给出明确错误。
- 正常应用的现有 UI 和生命周期不改变。

## 官方市场刷新

官方应用市场页面首次挂载时主动执行一次 `refresh_official_plugins`，读取远程仓库的最新 `aidea.yaml`；刷新期间显示加载状态。手动刷新按钮仍保留，用于重试和更新。

刷新失败不清空上一次成功缓存：展示缓存内容，并在市场页面显示刷新错误。市场刷新失败也不能影响 aIdea 壳或顶部应用菜单。

## 数据流

```text
启动 aIdea
  -> 加载内置/本地应用
  -> 逐项加载官方安装记录
  -> 正常定义返回 manifest / 异常定义返回 issue manifest
  -> 顶部菜单和应用管理继续渲染

打开应用市场
  -> 先显示缓存
  -> 主动刷新官方仓库
  -> 成功则替换缓存并更新列表
  -> 失败则保留缓存并显示错误
```

## 测试要求

- 单个官方应用缺少定义时，`list_apps` 仍成功，其他应用正常返回。
- 单个官方应用定义解析失败、进程启动失败、健康检查失败时，返回异常状态而不是壳级错误。
- 旧版无 `definition` 快照的安装记录不会导致整个应用列表失败。
- 顶部导航和应用管理能渲染异常 Badge 与错误信息。
- 市场页面首次打开会主动刷新；刷新失败仍显示缓存和错误。
- 正常官方应用的启动、停止、安装和更新测试保持通过。
