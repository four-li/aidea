# aIdea 应用设置与运行模式设计

## 目标

aIdea 是应用平台壳。内置应用和官方应用都遵守统一的应用契约，但业务配置由应用自己拥有和维护。

本设计解决以下问题：

- 应用可以提供自己的设置页面；
- 应用卸载后保留配置，重新安装后继续使用；
- 用户可以在 aIdea 中重置应用设置，并要求 Touch ID 确认；
- 内置应用也可以有独立设置；
- DevTools 可以预设多个工具，并允许用户隐藏不需要的工具；
- 官方应用可以脱离 aIdea 启动，但不重复建设一套平台壳。

## 核心边界

aIdea 管理平台级能力：

- 应用发现、安装、更新和卸载；
- 应用启动、停止、健康检查和日志；
- 顶层应用是否显示及其排序；
- 设置入口；
- 重置设置前的 Touch ID 确认；
- 数据目录、日志目录和敏感存储能力。

应用管理业务级能力：

- 配置页面和配置字段；
- 默认值、校验和保存；
- 配置版本与迁移；
- 业务数据库和业务文件；
- 配置重置的具体实现；
- 业务数据保留与清理策略。

aIdea 不解析官方应用或内置应用的业务配置字段，不建立所有应用共用的配置表，不允许应用直接读取 `shell.config.json`、`shell.db` 或 `secrets.db`。

## 应用类型

### 内置应用

内置应用随 aIdea 一起构建，不要求独立进程。它可以提供自己的设置页面和独立持久化数据，前端通过 aIdea 的内部 IPC 访问平台能力。

内置应用仍属于应用管理范围，但不具备官方应用的安装、更新和独立进程生命周期。

### 官方应用

官方应用位于独立仓库，由 aIdea 安装和运行。应用设置页面固定通过本地应用页面提供，默认入口为 `/settings`；健康检查入口为 `/health`。

官方应用的业务数据位于 `app-data/<app-id>/`，不得写入安装目录的 `source/`。

### DevTools 工具

DevTools 是一个内置应用，内部工具使用 tab 组织。Base64、Unicode、时间戳等轻量工具默认作为 tab，不因为需要显示或隐藏就拆成独立应用。

DevTools 的设置由 DevTools 自己管理，例如：

```json
{
  "hidden_tabs": ["unicode", "timestamp-converter", "ip-lookup"]
}
```

新增工具默认显示。用户隐藏的工具通过稳定的工具 ID 识别，工具更名或删除时由 DevTools 自己迁移配置。

只有在工具拥有独立业务数据、复杂设置、独立生命周期、独立升级需求或未来可能成为官方应用时，才拆成独立内置应用或官方应用。

## 设置入口契约

所有应用都提供设置详情入口。详情页统一留在 aIdea 设置弹窗内部：

| 应用类型 | aIdea 的动作 | 设置页面归属 |
| --- | --- | --- |
| 内置应用 | 在弹窗二级页打开注册的内置设置页面 | 应用自己的 React 页面 |
| 官方应用 | 启动应用并在弹窗二级页打开 `/settings` | 应用自己的 Web 页面 |

aIdea 的“应用管理”列表只显示设置入口和顶层显示开关；详情页不渲染应用字段，不依赖应用 DOM，也不保存应用表单状态。没有具体配置字段的应用显示空配置状态。

官方应用的设置页面必须使用本地服务地址。aIdea 等待 `/health` 成功后才允许打开设置页面。应用停止时，aIdea 先启动应用；应用运行时直接打开设置页面。

## 配置存储

配置归应用所有，存储方式按业务复杂度选择：

- 简单、非敏感配置可以使用应用自己的 JSON 文件；
- 有关联关系、历史记录或迁移需求的配置使用应用自己的 SQLite；
- 密码、OAuth Token、API Key 使用 aIdea 提供的敏感存储能力，禁止明文写入配置文件或业务数据库。

内置应用使用自己的数据库或专属配置文件；官方应用使用自己的 `app-data/<app-id>/`。两者都不能把业务配置写入 aIdea 的壳配置。

首次启动时应用创建默认配置。配置版本、默认值变化和数据迁移由应用处理，aIdea 升级或应用更新不得覆盖用户配置。

## 卸载、重新安装与更新

官方应用卸载默认只删除：

- 安装源码；
- 安装依赖；
- 运行时记录。

默认不删除：

- 应用配置；
- 业务数据库；
- 业务文件；
- 应用日志。

重新安装相同 `app_id` 时，应用读取原有数据并执行自己的配置迁移。应用 ID 安装后不可更名，否则无法可靠关联历史数据。

更新只替换 `source/` 和运行环境。应用必须在启动时完成配置兼容检查；配置不兼容时返回明确错误，不得静默删除或覆盖旧配置。

## 重置设置

重置设置是应用详情页中的独立危险操作，不等同于卸载应用或删除业务数据。

推荐流程：

```text
用户点击“重置设置”
  -> aIdea 发起 Touch ID
  -> 认证成功
  -> 停止正在运行的应用
  -> 调用应用声明的 reset command
  -> 应用只重置配置并保留业务数据
  -> 按原状态重新启动应用
```

应用的 reset command 必须：

- 使用参数数组，不使用 shell 字符串；
- 只修改配置范围，不删除整个 `app-data/<app-id>/`；
- 保留业务数据和数据库结构；
- 失败时返回非零退出码并保留原配置；
- 必要时先创建配置备份。

Touch ID 是 aIdea 的授权边界，不能由应用页面伪造或自行绕过。应用页面可以提供普通的“恢复某项默认值”，但完整配置重置必须经过 aIdea 的确认流程。

## 独立运行

独立运行分为三个层级：

| 层级 | 结论 |
| --- | --- |
| 开发时可直接启动和测试 | 必须支持 |
| 不依赖 aIdea 也能运行核心业务 | 建议支持 |
| 每个应用独立打包成完整桌面平台 | 当前不支持 |

官方应用运行时优先读取 aIdea 注入的环境变量：

```text
AIDEA_APP_ID
AIDEA_APP_DATA_DIR
AIDEA_APP_LOG_DIR
AIDEA_COMMAND
```

脱离 aIdea 启动时，应用使用自己的默认数据目录和系统敏感存储。应用可以使用一个很小的运行时适配层选择 aIdea 平台能力或独立运行时能力，但不得复制应用市场、更新器、进程管理和顶部导航。

独立运行的目标是便于开发、测试、故障排查和核心业务恢复，不是让每个官方应用变成一套完整桌面产品。

## 顶层应用与内部工具

顶层应用的显示状态由 aIdea 管理，例如 `app_settings[app_id].visible`。

应用内部工具的显示状态由应用自己管理。例如 DevTools 的 `hidden_tabs` 属于 DevTools 配置，不属于 aIdea 的顶层应用设置。

如果一个工具必须出现在 aIdea 顶层菜单、拥有独立设置或拥有独立生命周期，它必须成为独立应用并拥有自己的稳定 `app_id`。不能让 aIdea 把 tab 伪装成顶层应用。

## 测试要求

每个有设置的应用至少验证：

- 没有配置时能创建默认配置；
- 修改配置后重启仍能读取；
- 更新配置版本时能执行迁移；
- 卸载后重新安装能读取原配置；
- 重置配置不会删除业务数据；
- 设置页面在应用停止时可以由 aIdea 启动后打开；
- 官方应用在有无 aIdea 环境变量时都能完成对应运行模式的启动。

DevTools 额外验证：

- 默认显示所有已注册工具；
- 用户隐藏的工具不会出现在工具菜单；
- 新增工具不会因为旧配置而永久不可见；
- 至少保留一个可用工具入口，避免 DevTools 进入空白状态。

## 非目标

当前不实现：

- 通用配置 schema 和自动表单生成器；
- 所有应用共用的业务配置数据库；
- 第三方应用的设置兼容保证；
- 每个应用独立打包的桌面壳；
- 通过删除整个数据目录实现“重置设置”。
