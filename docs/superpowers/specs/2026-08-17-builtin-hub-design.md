# 开搞中心 UI 设计

## 状态

- 日期：2026-08-17
- 状态：待用户审阅
- 范围：aIdea 壳内置应用的统一入口和页面布局

## 背景与目标

aIdea 的 AI Service、DevTools 以及后续新增的内置应用都随壳发布，由同一团队维护。当前每个内置应用都作为顶部应用标签显示，应用数量增加后顶部入口会变长，内置应用之间也缺少统一的工作区入口。

本次调整的目标是：

1. 顶部只提供一个“开搞中心”入口，集中进入内置应用。
2. 在开搞中心内用窄图标栏切换内置应用，给应用自己的菜单和内容留下空间。
3. 保持 AI Service、DevTools 等应用的代码、数据、配置和业务职责独立。
4. 让后续新增内置应用只需要加入 manifest 和壳的显式渲染注册，不再增加新的顶部应用入口。

## 设计决策

### 开搞中心是壳级导航容器

“开搞中心”不是第三个内置应用，不新增 `builtin-center` manifest、应用数据库、业务版本或独立设置。它只负责：

- 提供顶部“开搞中心”入口。
- 展示可进入的内置应用图标。
- 切换当前内置应用。
- 在内容区域渲染当前内置应用入口。

AI Service、DevTools 和未来的其他内置应用仍然是独立应用，继续拥有自己的入口组件、业务状态、IPC、数据库和测试。

### 两层导航

```text
顶部：开搞中心
          |
          v
┌────────────┬────────────────────┬─────────────────────────┐
│ 内置应用栏 │ 当前应用自己的菜单 │ 当前应用自己的内容      │
│ 约 56-64px  │ 由应用自行决定      │ 由应用自行渲染          │
└────────────┴────────────────────┴─────────────────────────┘
```

#### 第一层：开搞中心应用栏

- 宽度固定在约 56-64px，只显示图标。
- 每个图标对应一个 `ui.mode: builtin` 且不是 `account-menu` 入口的内置应用。
- 图标使用 `lucide-react`，不使用 emoji 或手写 SVG。
- 每个图标按钮必须提供 `aria-label`，悬停显示 `Tooltip`，提示应用名称。
- 当前应用使用背景色和左侧选中标记表示，不仅依赖颜色；键盘焦点仍然可见。
- 应用栏只负责切换应用，不读取或修改应用业务配置。
- 开搞中心默认打开 `ai-service`；未来新增应用按 manifest 注册顺序追加。

#### 第二层：应用自己的菜单

- 菜单属于当前内置应用，开搞中心不定义统一的业务菜单协议。
- 应用可以选择 Tabs、侧栏或其他符合 UI 规范的局部导航。
- AI Service 首期保留现有的“模型配置、服务列表、模型测试、审计记录”菜单和状态管理；如实现时采用侧栏，只改变布局，不改变页面功能和数据契约。
- DevTools 首期保留现有工具 Tabs 和设置状态；开搞中心不解析工具 ID 或业务设置。
- 后续应用的菜单数量和层级由应用自己决定，不为未知需求提前增加全局分组、搜索或多级导航模型。

## 壳级导航与页面状态

壳维护两个相互独立的状态：

- 是否显示开搞中心。
- 当前开搞中心内选中的内置应用 ID。

官方应用仍使用现有的 `activeAppId` 和顶部标签切换逻辑。进入开搞中心时不创建伪 manifest；从开搞中心切换到官方应用时恢复现有官方应用选择逻辑。

首期不新增 URL 路由、跨应用状态持久化或全局二级菜单状态。应用内部是否保留自己的菜单选择状态，由应用按现有实现决定。

## 入口与显示规则

### 顶部栏

- 顶部固定显示“开搞中心”入口。
- 官方应用继续显示在顶部应用区域。
- AI Service、DevTools 和其他普通内置应用不再作为顶部独立标签显示。
- 开发手册继续只从右上角设置展开按钮组进入，不加入开搞中心应用栏。

### 应用管理

- 应用管理页移除内置应用卡片。
- 内置应用的业务设置不再从应用管理进入。
- AI Service 的模型、服务、模型测试和审计设置都从 AI Service 页面进入。
- DevTools 的工具显示、排序和相关设置从 DevTools 页面进入。
- 官方应用的安装、更新、启动、停止、日志和卸载管理保持不变。

## 内置应用注册与边界

继续沿用当前显式注册方式：

- Rust manifest 继续声明每个内置应用。
- `BuiltinPage.tsx` 继续显式把 app ID 映射到应用入口组件。
- 开搞中心应用栏从已加载的 manifest 中筛选内置应用，复用 manifest 的 `id`、`name` 和 `ui.icon`。
- 不新增自动扫描、插件市场、第三方应用注册或通用业务导航配置。

这样新增内置应用的最小步骤是：

1. 新增 `apps/builtin/<app-id>.yaml`。
2. 新增 `shell-frontend/src/builtin-apps/<app-id>/index.tsx` 和业务目录。
3. 在 Rust manifest 和 `BuiltinPage.tsx` 中完成显式注册。
4. 在开搞中心应用栏显示其 manifest 图标。
5. 为应用自己的页面和业务设置补充测试。

## 视觉与交互约束

- 开搞中心使用现有 shadcn/ui、Tailwind 主题 token 和 lucide 图标，不建立第二套 UI 组件库。
- 应用栏和应用内容区使用稳定宽度，避免切换时页面跳动。
- 浅色、深色主题都必须可读；图标按钮、焦点状态和 Tooltip 都要验证。
- 不使用卡片包卡片；页面分区使用完整宽度布局，卡片只用于独立的重复项或确实需要边界的工具区域。
- 窄窗口下应用图标栏保持可用，应用自己的菜单可以滚动；首期不增加移动端专用导航模式。

## 实现影响

预计涉及：

- `App.tsx`：增加开搞中心显示状态和当前内置应用选择，不新增伪 manifest。
- `TopBar.tsx`：移除普通内置应用标签，增加固定“开搞中心”入口；官方应用入口保持原行为。
- 新增壳级 `BuiltinHubPage`：实现图标应用栏和当前内置应用挂载。
- `ContentArea.tsx` / `BuiltinPage.tsx`：支持开搞中心容器和应用页面的分离渲染。
- `AppManagementPage.tsx`：移除内置应用卡片和业务设置入口。
- AI Service、DevTools：只做嵌入布局和入口调整，业务功能、IPC 和数据结构不改变。
- 相关前端测试：补充开搞中心默认应用、图标切换、官方应用入口和开发手册入口测试。

不在本次范围内：

- 改变 AI Service 的 `/api/agent` 契约。
- 重写 Rig Agent、工具或审计实现。
- 将开发手册移动到开搞中心。
- 增加内置应用市场、动态插件注册或跨应用共享状态。

## 验证标准

实现完成后至少验证：

1. 启动后顶部只有“开搞中心”和官方应用入口，默认进入 AI Service。
2. 图标栏可以切换 AI Service、DevTools 和后续内置应用，Tooltip 和键盘焦点可用。
3. AI Service 和 DevTools 的内部菜单仍能正常切换，切换外层应用不会出现内容重叠或高度塌陷。
4. 设置中的开发手册入口仍然可用，且不出现在开搞中心应用栏。
5. 应用管理不再显示内置应用业务卡片，官方应用管理功能不受影响。
6. 浅色、深色和窄窗口下无明显重叠、截断或不可操作控件。

按仓库约定执行前端 lint、测试和构建；如果实现触及 Rust manifest 或命令注册，再执行 Rust 测试。
