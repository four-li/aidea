# 官方应用启动失败重试设计

## 目标

官方应用因端口被占用等原因启动失败后，用户释放原因后可以在原位置直接重试，不必重启 aIdea。异常仍保留并展示，直到下一次启动成功。

## 范围

- 应用管理的更多操作菜单：已停止且有异常时显示“重试启动”。
- 顶部应用右键菜单：遵循同一规则。
- 平台规范：明确启动失败不锁死生命周期操作，以及进程接管的边界。

不新增开发服务接管模式，不改变进程管理器、IPC 或应用 manifest。

## 行为

1. 启动失败时，后端继续记录最新异常，前端继续显示异常原因。
2. 应用处于已停止、非过渡状态时：无异常显示“启动”，有异常显示“重试启动”。两者都调用既有 `start_app`。
3. 重试前不清除旧异常；启动成功后沿用现有后端逻辑清除异常。再次失败时以新的错误原因替换旧原因。
4. 启动中或停止中时只显示当前过渡状态，避免重复发起生命周期操作。
5. 已运行时保留既有停止和重启操作；异常标记不应隐藏这些操作。

## 本地开发服务

aIdea 只接管同时满足以下条件的遗留监听进程：

- 工作目录位于该官方应用的 aIdea 安装 `source/` 目录内；
- 对应 `ready_url` 的健康检查成功。

开发目录中手动启动的服务不属于接管范围。开发者关闭该服务后，通过“重试启动”由 aIdea 正常启动已安装版本。这样 aIdea 的停止操作只会终止自身管理的进程，不会误杀本地调试服务。

## 验证

- 前端组件测试覆盖：已停止且有异常时显示并可触发“重试启动”；启动中不显示该操作。
- 运行前端 lint、测试和构建，Rust 测试，以及 `git diff --check`。
