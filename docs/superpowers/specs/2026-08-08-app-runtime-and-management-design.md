# aIdea 应用运行时与管理设计

## 目标

aIdea 是装载内置应用与官方应用的本地壳。首期需要让官方应用的安装、启动、停止、异常恢复、日志、版本更新和卸载都有统一入口，避免重复启动、端口残留和不可解释的空白页。

本设计只覆盖内置应用与官方应用；不支持用户手动接入的第三方应用。

## 固定术语

| 术语 | 定义 |
| --- | --- |
| 内置应用 | 随 aIdea 发布包提供的页面，例如邮件管理、DevTools。不可卸载。 |
| 官方应用 | 从 aIdea 应用市场安装、由 aIdea 维护版本和运行定义的独立应用，例如股票助手。可卸载。 |
| 官方应用目录 | 随 aIdea 发布的官方仓库列表，只声明收录的应用仓库地址和启用状态。 |
| 应用市场 | aIdea 读取官方应用目录与应用定义后展示的官方应用安装入口。 |
| 应用定义 | 官方应用仓库根目录的 `aidea.yaml`，声明版本、源码 revision、安装命令、启动命令和本地健康检查地址。 |
| 用户应用设置 | 用户级持久化偏好，包括隐藏状态和启动方式。 |
| 运行记录 | aIdea 写入 `runtime/processes/<app-id>.json` 的短期状态，用于识别并接管异常退出后遗留的受管进程。 |
| 受管进程 | 由 aIdea 启动并已记录的官方应用进程。 |
| 外部进程 | 不是 aIdea 当前或上一实例启动的进程，即使占用了同一健康检查端口也不接管。 |

## 范围与非目标

首期范围：

- 官方应用默认手动启动，用户可逐个开启“随 aIdea 启动”。
- aIdea 退出时停止全部受管进程。
- aIdea 异常退出后，下次启动接管仍可验证的受管进程。
- 检测外部端口占用并清楚报告，不重复启动。
- 在应用管理中统一操作应用、查看运行状态和日志。
- 官方应用从其自身仓库的 `aidea.yaml` 读取版本与运行定义。
- aIdea 从 GitHub Releases 检查、下载和安装自身更新。

非目标：

- 常驻后台守护进程。
- 用户手动添加的第三方应用。
- 自动从未收录的仓库发现或安装应用。
- 自动重启崩溃的官方应用、资源监控、依赖编排。

## 数据边界

### 应用定义

官方应用目录与应用定义都是只读发布内容。官方应用目录随 aIdea 发布，只列出官方应用仓库地址和启用状态，不重复维护应用名称、版本、启动命令等信息。

每个官方应用仓库根目录必须提供 `aidea.yaml`。它至少包含 `id`、显示元数据、语义化版本、固定 revision、安装命令、启动命令、工作目录、健康检查地址、最低 aIdea 版本和更新说明。

应用市场刷新时，aIdea 根据内置目录读取每个应用仓库的 `aidea.yaml`，比较其版本与本机安装版本。安装与更新必须 clone 定义中指定的固定 commit SHA；不得直接安装 `main` 或其他浮动分支。定义中的版本必须递增；revision 变化但版本不变属于无效发布配置。

### 用户应用设置

用户设置保存到壳的用户级配置，不写回官方应用 YAML。每个应用的设置包括：

- `visible`：是否在顶部应用栏显示，默认 `true`。
- `startup_mode`：`manual` 或 `with-aidea`，官方应用默认 `manual`。

内置应用只支持 `visible`；官方应用支持两个字段。

### 运行记录

运行记录位于：

```text
~/Library/Application Support/aIdea/runtime/processes/<app-id>.json
```

记录只保存短期运行信息：应用 ID、PID、启动时间、当前应用版本、工作目录、健康检查地址、日志路径和实例标识。不得保存密码、令牌和业务数据。

子进程创建后立即写入状态为“启动中”的记录；健康检查成功后更新为“运行中”。健康检查失败或受管进程正常停止后删除记录；aIdea 异常退出时记录保留，以便下次启动恢复。

## 生命周期

### aIdea 启动

1. 读取所有运行记录。
2. 对每条记录验证 PID 存活、进程启动时间、命令与工作目录匹配，并验证声明的本地健康检查地址。
3. 验证成功则接管该进程，状态显示为“运行中（已接管）”。
4. PID 不存在或验证失败则删除旧记录，状态显示为“已停止”。
5. 对启动方式为 `with-aidea` 且未运行的官方应用启动新进程。
6. 若目标端口已被无法验证为受管进程的外部服务占用，显示“外部进程占用”，不尝试启动、不误接管。

### 手动启动

1. 已受管且运行中的应用直接返回现有实例，不重复启动。
2. 外部端口占用时返回可读错误，包含地址和端口。
3. 创建子进程、日志文件和运行记录。
4. 健康检查成功后状态变为“运行中”；失败时停止新进程、保留启动日志、清除运行记录并显示失败原因。

### 停止与退出

- 用户停止或重启时，先发送 `SIGTERM`，最多等待 5 秒，再发送 `SIGKILL`。
- aIdea 收到退出事件时，对全部受管进程执行同样的停止流程。
- 由用户在终端自行启动的开发服务或其他外部进程不是受管进程，aIdea 不停止它。

### 异常退出

子进程自然退出时，运行状态保存退出时间、退出码或信号和最后错误摘要；运行记录删除。应用管理与日志页展示该信息，方便定位启动失败或崩溃。

## 应用管理

设置中的“官方插件”改名为“应用市场”。“应用管理”是已安装应用的统一管理入口。

应用管理列表展示：图标、名称、类型（内置/官方）、已安装版本、运行状态、启动方式和隐藏状态。

内置应用：

- 可隐藏或恢复显示。
- 不显示卸载、更新和进程操作。

官方应用：

- 启动、停止、重启。
- 设置“随 aIdea 启动”。
- 隐藏或恢复显示。
- 卸载。
- 查看“运行与日志”。

“添加应用”按钮改为跳转到应用市场，不再创建手工 manifest。

### 运行与日志

应用详情中的“运行与日志”区域展示：当前状态、PID、启动时间、实例来源（本次启动或已接管）、最近退出原因，以及日志输出。

日志从应用日志文件末尾持续刷新，可暂停查看。启动和运行日志保留在：

```text
~/Library/Application Support/aIdea/logs/<app-id>/
```

## 应用市场

应用市场读取内置官方应用目录，再读取其中每个应用仓库的 `aidea.yaml`，只展示被收录的官方应用。aIdea 启动时不访问应用仓库；用户打开应用市场或点击刷新时才请求网络，并在本地保留最近一次校验成功的应用定义缓存。

- 未安装：显示安装。
- 已安装且版本相同：显示已安装，不显示更新。
- 已安装且市场版本更高：显示更新和更新说明。
- 已安装：可卸载。

卸载删除应用源码、安装状态、运行记录和受管进程；默认保留 `app-data/<app-id>/` 与日志，避免误删用户业务数据。后续若提供“同时删除应用数据”，必须作为单独的危险操作并二次确认。

## 隐私与关于

隐私与安全页仅显示：

> aIdea 本地应用不收集任何用户数据。

关于页读取真实应用版本，而不是写死的前端字符串。它展示当前版本、最新版本、更新说明与检查更新时间。

## aIdea 自更新

首期更新源是 GitHub Releases，不发布到 App Store。

1. aIdea 请求 GitHub Release 对应的签名更新清单。
2. 检查到高于当前版本的发布后展示更新说明。
3. 用户点击更新后下载 Tauri updater 包，验证签名。
4. 下载和验证成功后提示重启，重启时由 updater 替换 aIdea.app。

发布流程除 DMG 外必须生成签名 updater 产物与更新清单。将来若迁移公司内网或私有发布服务，只替换更新清单地址和发布流水线，不改变应用管理或官方应用市场。

## 官方应用目录与发布

官方应用目录随 aIdea.app 发布。新增官方应用时，需要在目录加入仓库地址并发布新版 aIdea；应用版本更新时，只需在对应应用仓库更新 `aidea.yaml` 和指定的固定 revision，aIdea 无需更新即可在下次市场刷新时显示更新。

目录文件位于 `plugin-markets/official/`，每个 YAML 只包含契约版本和应用仓库条目。例如：

```yaml
schema_version: 1
repository: https://github.com/four-li/stock-assistant.git
enabled: true
```

应用仓库根文件固定为 `aidea.yaml`。aIdea 使用内置目录指定的仓库读取此文件；随后根据文件中的固定 revision 安装或更新源码。

aIdea 必须校验目录与应用定义的格式、应用 ID 唯一性、最低 aIdea 版本、命令安全约束和本地健康检查约束。校验失败的应用不显示为可安装项，并在市场中给出可读错误。

## 实施顺序

1. 运行记录、受管进程接管、端口归属识别、退出清理和状态模型。
2. 用户应用设置与应用管理页重构，包括运行与日志页。
3. 官方应用目录读取、应用仓库 `aidea.yaml` 校验、版本比较、更新显示和统一卸载。
4. 隐私页与关于页真实版本信息。
5. GitHub Releases 的签名自更新链路与发布流程。

## 验收标准

- 官方应用默认不随 aIdea 启动；开启后重启 aIdea 会自动启动。
- aIdea 正常退出后，受管官方应用不再占用其端口。
- 模拟 aIdea 异常退出后，下一次启动能接管仍存活的受管应用，不重复启动。
- 外部程序占用应用端口时，应用管理显示外部占用且不误接管。
- 应用管理能区分内置与官方应用，完成隐藏、启动、停止、重启、日志和卸载操作。
- 更新已收录应用仓库的定义后，无需更新 aIdea 即可发现应用更新；新增官方应用需要发布新版 aIdea。
- 应用市场只有版本较新时显示更新，且安装版本始终对应声明的固定 revision。
- 关于页显示真实版本；GitHub 有签名新版本时可检查、下载并重启更新。
