# 应用管理边界设计

> **历史记录，禁止作为当前实现或发布步骤执行。** 本文记录本次边界调整的决策与验收依据，不是后续实现入口。现行规则以 `docs/guide/aidea-platform.md`、`docs/guide/aidea-official-app.md` 和 `docs/guide/aidea-app-bridge.md` 为准。

## 背景

现有设计把官方应用的业务设置页嵌入 aIdea 的“应用管理”详情页。结果混淆了两类完全不同的事情：

- aIdea 的运行管理，例如是否显示、是否随 aIdea 启动、更新、日志和卸载。
- 应用自身的业务操作，例如邮件账户、同步频率和服务商配置。

邮件中心的账户设置需要先进入“应用管理”才能操作，路径牵强；iframe 嵌入还会引入高度、滚动和应用内返回导航等额外问题。

本设计将两类职责彻底分开：应用管理只管理应用，应用业务设置只在应用自己的主页面完成。

## 目标

1. “应用管理”成为唯一的壳层应用管理页面，不承载官方应用的业务设置。
2. 官方应用的业务设置入口由应用自己定义并放在应用主页面中。
3. 移除官方应用的 `/settings` 和 `settings.reset_command` 平台契约。
4. 内置应用继续保留 aIdea 内的设置详情和配置重置，不影响 DevTools 等现有能力。

## 已确认的产品决策

### 官方应用

- 不显示齿轮设置按钮，不提供 aIdea 内的应用设置详情页。
- 不提供“打开应用”按钮；使用应用仍从 aIdea 主界面入口进入。
- 卡片保留“显示在主页”开关。它只控制该应用是否出现在 aIdea 主界面，不控制进程运行状态。
- 更多菜单保留启动、停止、重启、更新、日志和卸载。
- “随开搞启动”放在更多菜单中，以开关项表达。仅有独立进程的官方应用显示该项。
- 名称、图标、版本等发布信息只读，不支持用户在 aIdea 中改别名或自定义图标。
- 不声明、不使用 `settings.reset_command`。应用需要重置业务配置时，必须在自己的主页面实现。
- 不再要求 `GET /settings`，aIdea 不会请求或嵌入该路径。

### 内置应用

- 保留齿轮按钮和 aIdea 内设置详情页。
- 继续使用已注册的内置业务设置组件。
- 保留 `settings.reset_command` 和现有重置确认流程；该能力仅属于内置应用。

## 页面行为

### 应用管理

页面继续分为“已安装应用”和默认展开的“可安装应用”。

已安装区的官方应用卡片提供：

- `显示在主页` 开关。
- 更多菜单中的启动、停止、重启。
- 更多菜单中的 `随开搞启动` 开关。
- 有新版时的更新。
- 日志和卸载；卸载继续先弹确认，且保留应用数据和日志。

已安装区的内置应用保留现有齿轮入口。进入详情页后，aIdea 管理显示偏好、启动偏好，并按内置应用注册情况显示业务设置与重置配置。

不再将官方应用的网页或表单放入 iframe，因此不需要为业务设置页处理 iframe 高度、内部滚动或返回导航。

### 邮件中心

邮件账户管理是邮件中心的核心业务流程。添加、编辑、测试、删除账户的入口放在邮件中心主页面的明确位置，由邮件中心自行跳转或切换到自己的账户配置视图。

该配置视图仍由邮件中心读取和写入自己的 `AIDEA_APP_DATA_DIR/app.db`。aIdea 不读取账户、密码、授权码或同步配置，也不提供统一表单。

## 平台契约调整

### 保留

- `GET /health` 仍是所有官方应用的强制入口，且 `process.ready_url` 必须指向本地 `127.0.0.1` 的 health 地址。
- 主页面仍接收 `aidea_theme=light|dark` 首屏参数；主页面 `ready` 后仍通过 App Bridge 接收运行期主题、通知和应用内跳转消息。
- 官方应用继续只使用环境变量、自己的数据目录和 App Bridge，不使用 Tauri IPC。

### 移除

- 官方应用必须实现 `GET /settings` 的要求。
- aIdea 向官方应用 `/settings` 追加主题参数的行为。
- `/settings` 不参与 App Bridge 的例外说明。
- 官方应用 `aidea.yaml` 中的 `settings.reset_command`。
- aIdea 打开、嵌入或管理官方应用业务设置页的行为。

`settings.reset_command` 类型继续保留在内置应用 manifest 中。官方市场定义若出现该字段，后端应明确拒绝，避免以后又把业务重置能力带回官方应用管理。

`reset_app_settings` 后端命令继续服务内置应用；它应拒绝对非 `builtin` 应用执行重置。这样旧安装记录即使还留有历史 `settings` 快照，也无法通过壳触发官方应用重置。

## 迁移与兼容

- 已安装的旧官方应用即使还提供 `/settings` 或安装记录中带有 `settings.reset_command`，aIdea 新界面也不显示设置入口，不调用 `/settings`。
- 不迁移、不删除官方应用已有业务数据、数据库或日志。
- 新版官方市场定义禁止 `settings.reset_command`；应用移除 `/settings` 不影响安装、启动、健康检查、更新和卸载。
- 邮件中心发布包含主页面账户入口的新版后，用户通过官方市场更新即可获得新流程；不需要重装或迁移账户数据。

- `AGENTS.md` 的平台边界与文档路由。
- `docs/guide/aidea-platform.md`。
- `docs/guide/aidea-official-app.md`。

文档需要明确：官方应用的设置由应用主页面自行组织，aIdea 应用管理只管理壳层偏好和生命周期。

## 实施范围

### aIdea 仓库

- 调整 `AppManagementPage`：官方应用不显示齿轮；菜单增加“随开搞启动”；显示开关改为“显示在主页”。
- 保持内置应用的 `AppSettingsDetail`，但限定为内置应用调用。
- 移除 `WebviewFrame` 用于官方应用 `/settings` 的路径。
- 将官方市场校验改为拒绝 `settings.reset_command`。
- 限制 Rust 重置命令只能处理内置应用。
- 更新类型、测试、文档、参考应用和 `$aidea-app` Skill。

### mail-center 仓库

- 从 aIdea 入口移除依赖：不再把 `/settings` 作为壳调用的设置页。
- 在主页面增加清晰的账户设置入口，并保持现有账户表单、验证、保存和删除能力。
- 调整应用路由与页面导航，确保账户设置返回邮件中心是应用内部流程。
- 由于用户可见界面和交互变化，递增 mail-center patch 版本并按官方应用发布流程更新市场包和 `aidea.yaml`。

## 验收

1. 官方应用卡片没有齿轮按钮，内置应用仍有。
2. 官方应用更多菜单可切换“随开搞启动”，且只影响 `shell.config.json` 的启动偏好。
3. 官方应用的“显示在主页”不影响进程状态；关闭后应用仍在应用管理中可更新、查看日志和卸载。
4. 官方应用不再加载 `/settings`，旧 `/settings` 即使存在也不会被 aIdea 调用。
5. 官方市场拒绝含 `settings.reset_command` 的新定义；对旧官方应用调用重置命令会被后端拒绝。
6. 内置应用的设置详情和重置配置回归测试仍通过。
7. 邮件中心从主页面即可完成账户添加、编辑、测试和删除，无需打开 aIdea 应用管理。
8. aIdea 和 mail-center 均验证浅色、深色主题以及官方应用的安装、更新、启动和卸载主链路。

## 非目标

- 不支持用户自定义官方应用名称或图标。
- 不新增全局应用设置协议、统一业务表单或共享配置数据库。
- 不改变官方应用数据目录、健康检查、安装包或 App Bridge 主页面通信契约。
- 不处理第三方应用市场和多作者扩展能力。
