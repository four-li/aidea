# AI 模型测试界面优化设计

## 目标

优化 DevTools 的 AI 模型测试页，让它更适合后续扩展图片生成、视频生成等能力，同时保持当前请求模板和响应结果的左右双栏工作流。

## 已确认方案

采用“左侧一级菜单 + 右侧内容区”的布局。

- 左侧菜单承载功能入口：连通性、查询用量、模型列表、图片理解，后续可继续加入图片生成、视频生成。
- 右侧顶部保留共用连接配置：App Key、Base URL、Model、历史配置。
- 右侧主体继续使用左右双栏：左侧请求模板，右侧响应结果。
- 发送按钮放进请求模板框内右下角，避免按钮挤在双栏标题区，左右框视觉更对齐。
- “多模态”菜单改名为“图片理解”。

不采用把配置放进左侧菜单或每个功能内部重复配置的方案。连接配置是所有 AI 能力的共用上下文，固定在右侧顶部更直观，也能减少状态同步问题。

## 模型列表

Model 初始化为空，不再要求用户手工输入。

- Model 使用下拉选择控件。
- 模型下拉旁保留同步按钮。
- 用户点击同步按钮时，通过现有通用 AI HTTP 请求能力调用 `{{baseUrl}}/v1/models`。
- 请求成功后，从响应中读取 `data[].id` 填充下拉列表；如果当前没有选择模型，默认选中第一项。
- 请求失败时弹出 toast 报错，错误文案说明“模型列表拉取失败”，并展示后端返回的错误信息。
- 同步时按钮显示加载状态，避免重复点击造成并发请求。

这里不新增后端命令。现有 `send_ai_http_request` 已经能发送 OpenAI-compatible HTTP 请求，前端复用它即可。

## 图片理解

图片理解比其他功能多一个图片输入区，放在左侧请求模板上方，作为紧凑附件条。

- 未上传图片时显示“选择图片”入口和大小提示。
- 已上传图片后显示文件名、大小和删除按钮。
- 图片大小上限继续使用现有 5MB 规则。
- 未上传图片时，图片理解的发送按钮置灰，避免把空的 `{{imageData}}` 发给服务商。
- 超过大小限制、文件读取失败时，用 toast 展示错误。
- 发送请求时，图片以 data URL 替换模板里的 `{{imageData}}`。

图片上传只服务于图片理解功能，不移动到全局配置区，避免其他功能看到无关控件。

## 响应与提取结果

右侧结果区分成两层：原始响应在上，提取结果在下。

- 原始响应始终显示，便于排查接口状态、错误体和完整返回。
- 只有当前模板定义了 `extractor` 且有提取输出时，才显示“提取结果”区域。
- 提取结果区域固定在右侧下方，使用独立滚动，不把原始响应挤没。
- 请求失败时优先显示错误信息，不展示过期的上一次响应。

这样能兼容连通性、模型列表、图片理解等不同模板，同时不引入额外结果页或复杂解析器。

## 错误处理

- 模型列表同步失败：toast 报错，保留当前模型选择和已有模型列表。
- 普通请求失败：右侧结果区展示错误信息。
- 图片上传失败：toast 报错，保留未上传状态。
- API Key、Base URL 为空时，沿用现有请求失败路径，不额外增加表单系统。

## 测试范围

本次实现需要更新前端测试。

- 验证点击模型同步按钮会调用 `/v1/models`，成功后模型下拉出现返回的模型。
- 验证模型同步失败会展示错误，不清空已有配置。
- 验证发送请求使用下拉选择的模型。
- 验证图片理解未上传图片时不能发送，上传后可以发送并替换 `{{imageData}}`。
- 验证有提取结果时右侧显示“提取结果”，无提取结果时不显示该区域。

cd shell-frontend && npm run lint && npm test && npm run build
cd ../shell-native && cargo test
